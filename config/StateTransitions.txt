	startedOnResume -- startContactInfo() --> startedEditContactInfo
	// The summary is edited inline on this page, so startSummary() opens,
	// fills and saves it in one go -- there is no separate summary page to
	// land on, and waiting for one looped back to the top of the resume.
	finishedEditContactInfo -- startSummary() --> finishedEditSummary
	finishedEditSummary -- startWorkExp() --> finishedEditWorkExp
	finishedEditWorkExp -- startEdu() --> finishedEditEdu
	finishedEditEdu -- startSkills() --> finishedEditSkills
	finishedEditSkills -- finishResume() --> finishedResume
	// Still on the resume page after finishResume() means the exit did not take.
	// Without this line the state fell through to the default below and the
	// ENTIRE resume was redone -- one run did it five times, deleting and
	// re-adding the same four jobs each pass. Retry the exit instead; if it
	// cannot leave, finishResume() stops and asks for a person.
	finishedResume -- finishResume() --> finishedResume
	default -- startAtTopOfReviewPage() --> startedOnResume

// Indeed's AI-tailored resume review. Click Continue, tick the 'I have
// reviewed all changes made by AI' box in the dialog that appears, then click
// the dialog's own Continue. Its controls use data-tn-element rather than
// data-testid, so the ordinary Continue selectors do not see them.
//
// Matched on URL, not title. This used to be `((.*))|((.*))tailored
// resume((.*))` -- title-only. Confirmed live (Logs/Log23.txt) that the URL
// settles to /tailored-resume/resume?draft_id=... within ~2 seconds
// (rememberApplicationUrl caught the continue= param that fast) while the
// title NEVER updates to mention "tailored resume" at all -- this route
// does not touch document.title, so no amount of grace period was ever
// going to make the old rule match; it just sat in UNKNOWN PAGE until
// someone clicked through by hand, every single time.
//
// The literal prefix has to be this specific (not just "tailored-resume/")
// to outrun "((.*))|Upload or (((build|create))) a resume for this
// application((.*))" on length: with the stale title left over from the
// resume-selection page, that ANY-url rule also matches, and longest-wins
// would hand this page to startResume() instead -- clicking a "select a
// resume" radio card that is not on this page at all.
https://profile.indeed.com/tailored-resume/resume?draft_id=((.*))|((.*))
	default -- confirmTailoredResume() --> finishedResume
